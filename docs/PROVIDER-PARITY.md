# Provider Parity Matrix

The six providers deliberately do NOT behave identically — each difference below is either grounded in a provider's real constraints or is an accepted gap with the reasoning recorded. This doc exists so a difference is never mistaken for an oversight (and so a future "align X across providers" idea starts from the actual rationale). Found by the 2026-07-02 audit; companion to ADR-128. The Grok column was added additively with ADR-146; the other columns keep their original rationale and citations.

Factory defaults are literals (`FACTORY_DEFAULT_MODEL` in each package's `constants.ts`); the live default may differ via `ASK_<PROVIDER>_MODEL`.

Shared MCP behavior (identical everywhere, enforced by shared code + tests): 25s keep-alive progress (`registerTools`, ADR-053), `askResponseSchema` structured output, 100KB prompt cap, cancellation propagation, and duplicate-tool-name fail-fast.

Known deliberate NON-alignments to leave alone unless a user asks:
- **Timeout spread (210s–800s)** encodes real model behavior differences, not inconsistency.
- **"Session ID" vs "Thread ID"** labels match each CLI's own vocabulary; renaming would break users' mental mapping to `codex resume`.
- **Ollama's missing edit mode and no-fallback** are product decisions (#191, ADR history), not backlog.
- **Ollama and Grok have no model fallback for different reasons:** Ollama must run the locally pulled model; Grok's API request is an explicit metered model choice. Neither silently substitutes.
- **Grok reasoning variants are request parameters, not invented model slugs.** Discover model IDs through `GET /v1/models`; send the chosen ID unchanged. `xhigh` is documented for grok-4.6 and later; xAI applies it as `high` on older models, which Ask LLM discloses rather than masking.
- **Harness and model are separate (ADR-146).** `ask-grok` selects `xai-api` or `grok-cli` explicitly; unified startup probes whether either direct Grok harness is ready because request-level harness selection happens later, so an authenticated CLI-only installation is loaded without `XAI_API_KEY` or `ASK_GROK_HARNESS`; an explicit `ASK_GROK_HARNESS` narrows readiness to that configured default. This broad readiness check is not fallback: execution still selects exactly one requested/default harness and a failure never tries the other; a default-route call without `XAI_API_KEY` on a CLI-only machine fails with a diagnostic naming the explicit `harness: "grok-cli"` pin or `ASK_GROK_HARNESS=grok-cli`. The unified and Pi `ask-cursor-agent` tool requires a canonical provider family (`claude`, `codex`, `gemini`, `grok`) plus an exact account catalog model ID, verifies the requested ID against that family before spawn (refusing mismatches, Cursor Auto, and other noncanonical IDs), echoes that exact ID as `model`/`usage.model`, and returns Cursor's `system/init` display label as optional `reportedModel` (terminal error only when the label reveals a cross-provider substitution).
- **Large prompts use each harness's own path.** Codex/Gemini pipe over stdin above `EXECUTION.STDIN_THRESHOLD_BYTES`, Claude always uses stdin, Grok CLI uses a capability-probed private `--prompt-file`, Cursor Agent pipes over stdin, and Antigravity warns about ARG_MAX (spec §10.1).
- **Unified options fail closed.** `ask-llm` forwards `includeDirs` only to Codex/Claude/Antigravity and `reasoningEffort` only to Codex/Grok; unsupported combinations are schema errors rather than silently stripped options, and `includeDirs` on a resumed Codex session is rejected once in the shared `executeCodexCLI` boundary (split, unified, and Pi transports). Cursor Agent accepts validated relative `includeDirs` through repeated `--add-dir`, returns the structured conversation ID, and resumes it with `--resume` while preserving provider + exact model attribution.
- **Grok does not enable xAI storage or server-side tools.** `store:false` and no tools keep API consultations one-shot and cost-bounded. Grok CLI runs one read-only turn. Cursor Agent runs `--mode ask` without `--force` or automatic workspace trust.
- **Claude host suppression** is intentional: Claude Code rejects nested Claude Code sessions, so `ask-llm-mcp` exposes Claude only to Codex and other non-Claude-Code hosts.
- **Codex review/brainstorm model:** GPT-5.6 replaces the separate Pro slug with
  the Sol flagship, so `/codex-review`, `/brainstorm`, `/multi-review`, and
  `codex-pair` use `gpt-5.6-sol` by default and fall back to `gpt-5.6-terra`.
  `ASK_CODEX_PREFERRED_MODEL` remains a compatibility escape hatch; the raw
  `ask-codex` tool only attempts it separately when `preferred: true` and its
  value differs from `ASK_CODEX_MODEL`.
