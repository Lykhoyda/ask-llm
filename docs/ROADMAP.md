### 2026-06-30 — Graceful pinned-fallback message in the published `codex-mcp` executor (ADR-127, closes #196)

### 2026-06-20 — Codex quota-fallback model `gpt-5.5-mini` → `gpt-5.4-mini` (branch `fix/codex-fallback-gpt-5.4-mini`, ADR-126, closes #194)

The 2026-06-19 drift-audit (#194) flagged the Codex quota fallback `gpt-5.5-mini` as a non-existent model. The framing was imprecise but the bug was real: a live probe on this machine's ChatGPT-plan codex (CLI 0.141.0) showed `codex exec -m gpt-5.5-mini "ping"` returns `400 "not supported when using Codex with a ChatGPT account"` (an account-type restriction, not a 404) while `gpt-5.4-mini` answers `pong`. The ADR-123 structural-unavailability handling stays as a defensive guard for users who *pin* an unavailable model via `ASK_CODEX_FALLBACK_MODEL`. Primary `gpt-5.5` default unchanged; API-key users wanting `gpt-5.5-mini` can pin it. Swept current/user-facing docs (root + package READMEs, docs site, `llms-full.txt`) to the new slug; left historical records (ADR/ROADMAP/BUGS/CHANGELOG/plans) immutable per the ADR-067 precedent. Verified: live probe + `ask-codex-mcp` 90 tests + `@ask-llm/plugin` 415 tests green (drift guard + structural-unavailability). Supersedes ADR-067's fallback choice, refines ADR-123 alt-(b); ADR-126. ### 2026-06-18 — Antigravity default → Gemini 3.1 Pro (High) + Flash rate-limit fallback (ADR-125)

Flipped `ask-antigravity`'s default from Gemini 3.5 Flash (High) to **Gemini 3.1 Pro (High)** (the strongest reasoning tier for the second-opinion/review workload) and, for the first time, gave the provider a fallback: a rate-limit-only retry on **Gemini 3.5 Flash (High)**, mirroring the cross-tier quota fallback `ask-gemini` and `ask-codex` already use. Mechanically, extracted a `runWithModel(model)` closure so each attempt stamps its own `startedAt` (the transcript scraper reads files written after that mark — a reused timestamp would risk the fallback reading the rate-limited primary's absent transcript), with the whole try/fallback kept inside `withMutex` to preserve the no-concurrent-`agy` correctness lock. Fallback fires only on `isRateLimitError`; non-rate-limit failures (auth, not-installed, timeout) surface as-is and never mask as `RATE_LIMITED`; if the resolved model already is the fallback there is nothing to retry. Deliberately the *inverse* of the #191 Ollama no-fallback change (that removed a *silent same-family* substitution; this adds an *observable cross-tier quota* one — `AskResponse.model` reports the tier that answered). Updated the tool description, llm-mcp registry `defaultModel`, brainstorm-coordinator pin (raw path documented as fallback-exempt), package/docs/root README. Unit suite 35 green (4 new fallback tests), build + llm-mcp typecheck clean, and verified live against `agy` 1.0.6 (local executor → `agy --model "Gemini 3.1 Pro (High)"`, exit 0 in 13.9s, structured `model` = Pro). Changeset `antigravity-default-pro-flash-fallback` (minor `ask-antigravity-mcp`, patch `ask-llm-mcp` + `@ask-llm/plugin`); ADR-125.

### 2026-06-09 — codex quota fallback fix for CLI 0.137+ (branch `fix/codex-usage-limit-quota-detection`, ADR-117)

Found while pushing the gpt-5.5 doc-sync (PR #172): the local codex smoke hard-failed on a quota error. Root cause = ADR-044's pattern recurring for Codex. Codex 0.137 reports plan exhaustion as `"You've hit your usage limit"` on **stdout JSONL** (exit non-zero, benign stderr), but (1) `executeCommand` discarded stdout on non-zero exit so the quota text never reached `isQuotaError()`, and (2) `QUOTA_SIGNALS` lacked the phrasing — so the gpt-5.5→gpt-5.5-mini fallback silently never fired for real users.
